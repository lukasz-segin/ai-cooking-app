# Deploy the demo

This file prepares a public demo. It does not create accounts or deploy the app.

## Host choice

Use **Neon** for Postgres and **Render** for the app.

Neon has a free Postgres tier with the `vector` extension and nothing else you have to turn off. Render can run the existing Docker image. Its free web service sleeps when idle and cold-starts on the next request. The paid web service is about $7 per month if you do not want sleep.

Railway gives a small monthly credit and then bills, including while the service is quiet. Fly.io can stop machines when idle, but the config is heavier for the same demo. Supabase also has pgvector and also pauses inactive free projects.

## What you do by hand

1. Create a Neon project and copy its Postgres connection string.
2. Confirm `vector` is available. The app creates it in `documents_processor/migrations/0001_initial.py` (`CREATE EXTENSION IF NOT EXISTS vector`) because the embedding column needs that type on a fresh database. `init-db.sql` stays for local Docker only.
3. Create a Render web service from this repo using `render.yaml`. Keep auto-deploy off. Set the service branch to `master`.
4. Set these secrets on Render. Do not commit them.
   - `DATABASE_URL` from Neon
   - `OPENAI_API_KEY` — a key used only by this demo
   - `ALLOWED_HOSTS` — the Render hostname
   - `CSRF_TRUSTED_ORIGINS` — `https://` plus that hostname
   - `SECRET_KEY` is generated by `render.yaml`
5. In the OpenAI dashboard, set a monthly spending limit on that key.
6. In GitHub, add the repository secret `RENDER_DEPLOY_HOOK_URL` (Render → service → Deploy Hook).
7. After the first boot, run `python manage.py createcachetable` once in the Render shell. Throttling uses that shared database cache. The release command runs `migrate` only.
8. Push `devel` first. Merge `devel` into `master` only when you want the public branch updated. GitHub Actions runs tests on every push and pull request. It calls the Render hook only for a push to `master` after tests pass.
9. Open `/healthz`. It should return `{"status":"ok"}` when the database connection works.

Google Drive is optional. The app starts without `service-account.json`. Drive actions build a client only when that file exists, and they still require a staff user.

The public database starts empty. Cookbook files stay in local `private_data/` and are not loaded on deploy.

## Cost and shutdown

If the Render free tier is exceeded, the service stops until you upgrade or the quota resets. Neon pauses or limits the free database when its quota is used up. Either one takes the demo offline.

To stop recipe generation without deleting the service, set `RECIPE_GENERATION_ENABLED=false` and redeploy. `POST /api/recipes/generate/` then returns HTTP 503 and does not call OpenAI. To shut the demo down, suspend the Render service and rotate or delete the demo OpenAI key.

## Rotating the OpenAI key

Create a new demo key, set the spending limit, replace `OPENAI_API_KEY` on Render, redeploy, then revoke the old key.
